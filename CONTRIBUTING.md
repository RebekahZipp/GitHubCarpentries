# Contributing to GitHub Carpentries

This lesson is being built with the tools it teaches.

Carpentries instructors are invited to review the lesson, test the workflow, and contribute teaching experience.

## Start here

Read the root `README.md`, then follow the path that fits your review:

- `student/README.md` — learner-facing path
- `instructor/README.md` — teaching path and live lesson log

## What feedback is useful?

Please look for places where a novice may lose the thread.

Useful contributions include:

- clearer low-level language
- better Carpentries pacing
- missing teaching moments
- troubleshooting and recovery steps
- commands that need more context
- places where Git, GitHub, RStudio, or the Terminal are easy to confuse
- suggestions for exercises or checks for understanding
- accessibility and inclusive-teaching improvements

## Our teaching rhythm

The learner workflow is:

**CHANGE → INSPECT → CHOOSE → RECORD → REVIEW → SHARE**

The instructor also watches:

**ACTION → RESULT → CONCEPT → TEACHING MOMENT → RECOVERY**

Please preserve that rhythm when proposing changes.

## Ways to contribute

### Small comment or teaching suggestion

Open an Issue. Describe what you noticed, where it occurs, and what you would try instead.

### Proposed lesson change

Fork the repository, make a small focused change, and open a Pull Request.

A useful contribution does not need to be large. One clearer explanation or one tested recovery step is enough.

## Contribution rhythm

**READ → TEST → NOTICE → CHANGE → EXPLAIN → SHARE**

When possible, tell us why the change helps a learner or instructor. The reasoning is part of the lesson history.

## Current review question

Can another instructor use these materials to teach the workflow without needing to reconstruct the reasoning behind it?

That is the standard we are working toward.
